# V24 — 时间安排与子事项节点

用户已在本轮明确要求发布新版，并追加“子事项就是关键节点，支持配置子事项时间点”。本版合并发布 V23 月历密集展示修复与新的时间交互。

## 用户可见行为

- 删除独立“关键节点”编辑区。子事项同一行管理名称、完成状态、可选日期和具体时间。设置了时间的子事项就是日历节点；清除时间后保留为普通子事项。
- 旧 milestones 按名称与日期合并进子事项的读取视图，已有子事项的完成状态与具体时间优先保留；碰撞或不同日期记录不丢弃。打开抽屉不会自动保存；用户保存后写入 subtaskNodesVersion=1 与统一子事项。旧 milestones 原字段保留供恢复和旧版兼容，节点展示、修改、删除均读取统一子事项，删除后不复活。
- 有父计划周期时，子事项节点须在周期内。没有计划周期也可配置独立子事项时间点。跨天计划移动会同步移动节点日期并保留时刻，缩短周期不会静默丢弃节点。
- 日历柱状标出子事项节点，周视图与当天详情展示名称、时刻与完成状态。无父周期的子事项在自身日期独立展示。节点不占用日程时间轴。
- 计划周期、实际日程、截止时间分开设置。支持多个单次日程、周期内每天（含周末）、调整单日或整组、移除某日；周期结束后停止。日历拖动和拉伸写回对应的实际日程。
- 日程冲突、超出周期、晚于截止、超出 AI 时段提示。手动用户可继续；AI 自动排期时段限制在执行边界强制校验。
- 相对提醒可关联截止、日程、每日安排和子事项节点，跟随目标时间改变；已完成子事项不提醒。每日过去的提醒不补发。提醒仅在网页打开时运行，系统通知须主动授权。
- 支持每天、工作日、每周、每月重复，间隔、按计划/完成日期、截止日期与次数。完成后创建下一条并保留历史，重置子事项状态、相应顺延日期。
- 月视图最多直接展示 3 条跨天轨道，+N 打开完整列表，沿用 V23 修复。

## 数据和运行边界

- 未做云端迁移，未更换浏览器存储键，未操作用户浏览器中的真实数据；不能声称已备份用户数据。固定 V9 基准保存版本保留。
- 新 timePlan 是逐条按需写入的附加字段。原 scheduledStart/End 等字段不作全量重写。旧跨天区间按计划周期读取；旧单日日程按实际日程读取。
- 原有跨页面锁、保存时最新数据校验、AI 批次冲突校验均保留。四象限修改子事项也新增原子保存前比对，防止覆盖其他页面的新日期。
- 预计用时功能保留。GEMINI_API_KEY、GEMINI_MODEL、AI_OWNER_EMAIL 运行环境与 AI 所有者限制保持。
- V9 代码回退与数据恢复是不同操作；数据回退仍须先创建恢复快照。
